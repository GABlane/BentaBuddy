# Hackathon disclosures

- Product: BentaBuddy, a local-AI order and booking manager for Filipino Facebook Page businesses: bakeries/food sellers, gadget shops, staycation hosts, and general sellers/service providers. Submission overview: [SUBMISSION.md](../SUBMISSION.md).
- Application implementation: created during this hackathon workspace session. No earlier study-app code is used in the final product. Review the repository history and team contributions before making any event submission claim.
- AI-assisted development: OpenAI Codex assisted with research, product planning, application code, styling, documentation, and tests. Earlier brainstorming used Codex agents. Codex is a development tool; the product does not call OpenAI or other cloud AI APIs.
- Product model: pretrained Qwen3 4B, quantized GGUF distributed as Ollama `qwen3:4b-instruct-2507-q4_K_M`; no original training or fine-tuning claimed. Model license: Apache 2.0. Source: https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M and https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507.
- Model blob SHA-256: `85e4a5b7b8ef0e48af0e8658f5aaab9c2324c76c1641493f4d1e25fce54b18b9`. Verified locally after download.
- Runtime: bundled llama.cpp executable from official Ollama v0.40.2 Darwin archive; Ollama is an optional alternative. Preserve accompanying third-party license notices in the downloaded runtime. Runtime source: https://github.com/ollama/ollama and https://github.com/ggml-org/llama.cpp.
- Core dependencies: React, Vite, TypeScript, Lucide icons, FastAPI, Pydantic, Uvicorn, HTTPX, SQLite. Exact dependency versions are in package-lock.json and requirements.lock.txt; dependency licenses remain with their distributions.
- Logo: the BentaBuddy logo was made by the team (public/assets/benta_buddy_logo.png and benta_buddy_text.png). The app uses cropped, resized copies from public/assets/brand/.
- Visual assets: CSS, the Archivo typeface (SIL Open Font License, bundled locally from the @fontsource-variable/archivo package), Lucide icons, and platform-rendered Unicode emoji. No stock photos, remote fonts, or paid assets. An AI-generated bakery image from an earlier sign-in screen remains at public/assets/bakery-login.jpg but is no longer displayed. Image generation is not called by the running app.
- Demonstration records: starter catalogs and optional labeled sample conversations/orders are synthetic, not evidence of real sales. Fresh installations seed catalogs without fictional activity. The team's live Page tests also created actual received messages/customer profiles; do not describe those personal records as synthetic or expose them in a public video without permission. Use fictional records for submission visuals.
- Local boundary: conversation interpretation, order validation, SQLite storage, dashboards, and reports run on the owner's Mac. Phone/browser renders the app. Model download, dependency installation, and live Facebook message receipt need internet. Meta processes Messenger messages as the external messaging provider; no claim that Messenger itself works offline.
- Integration status: webhook code is implemented and tested with synthetic signed requests. The owner confirmed live Page message receipt, customer profiles, and extraction/corrections during development. Public-customer access remains dependent on Meta permissions/approval; eligible-account testing does not establish general public access. No automatic customer replies or historical inbox retrieval.
- Validation status: 52 automated tests and the production build pass as of October 10, 2026. Automated model responses are mocked. Separate real local CPU model checks passed core order scenarios and all four business themes with temporary databases and a CLI transport substitute. See [AI_VALIDATION.md](AI_VALIDATION.md) for failures, fixes, scope, and timings. These checks do not verify running-server HTTP/browser behavior or establish general model accuracy.
- Deployment scope: single-owner local prototype with no sign-in. Phone mode exposes the application to devices on the trusted local network; the phone is a browser client, not the AI host. Business themes do not create isolated shop accounts. No public production deployment claimed.

- Optional Facebook transport: Cloudflare Quick Tunnel via cloudflared, forwarding only the webhook relay. Cloudflare is a network transport provider, not an AI inference provider. The owner confirmed live tunnel operation, Meta delivery, and local extraction/correction through screenshots on October 9, 2026.

Optional customer profiles: Meta User Profile API uses a backend-only Page token to fetch customer names/photos when permitted; bounded photos are cached locally. This is a Facebook data lookup, separate from local AI inference. The owner confirmed profiles during development; access for other accounts remains permission-dependent.

The owner also confirmed live customer names/photos and offline operation. Request scoping now excludes reviewed messages and closed-order context; explicit selection separates new purchases while an earlier order remains open.
